# Шаблон слайд-плана занятия

> Копируйте этот файл в папку занятия как `slides-plan.md` и заполняйте.
> Типы слайдов и их поля — по справочнику `slides.md` (в корне проекта).
> `welcome` и `congrats` в план занятия НЕ включаются — они на уровне своего курса: `sem1/course-slides.md`
> и `sem2/course-slides.md` (семестры на платформе — два отдельных курса).

## Шапка

```markdown
# Занятие NN. «Название»
> Семестр X · Блок <название> · Курс NN (лекции ..) · ~N ч

## Миссия занятия
«Цитата/приказ Василича» — краткое описание квеста, что студент должен сделать и зачем.

## Итог занятия
Что студент получает в конце (артефакт: отчёт, агент, чат-бот и т.п.).
```

## Сводная таблица слайдов

```markdown
## Слайды

```

## Типы слайдов (шпаргалка по `slides.md`)

| Тип | Использование в курсе |
|---|---|
| `image_group` | комикс-панели, «ранее в сериале», развязка, схемы-иллюстрации |
| `rich_text` | теория, миссия, инструкции, итог (Markdown + LaTeX) |
| `image` | одиночные схемы/скриншоты |
| `video` | видеоурок (YouTube / MP4) |
| `code` | запуск кода с проверкой `expected_output` |
| `jupyter` | интерактивный Python-REPL (pyodide) |
| `terminal` | shell в песочнице: установка инструментов, рендер видео, работа с файлами (секреты — в `.env`) |
| `ai_code_task` | «агент пишет код, студент запускает и проверяет»: чат с AI-кодером + редактор + проверка |
| `quiz` | контрольная точка с вариантами |
| `open_question` | открытый вопрос с проверкой (короткий ответ) |
| `ai_chat` | свободный диалог с AI-персонажем (напр. «Василич-5.7») |
| `ai_comparison` | сравнение 2–4 моделей рядом |
| `ai_task_chat` | диалог с AI как задание с проверкой (`checkPrompt`) |
| `ai_fixed_answer` | чат + фиксированный ответ |
| `ai_image_gen` | свободная генерация изображений |
| `ai_image_task` | задание на генерацию изображения с проверкой |
| `llm_playground` | песочница параметров: температура, top-p, max_tokens, few-shot |
| `embed` | встроенный web-инструмент (tiktokenizer, TokenProbe, bbycroft и т.п.) |
| `resources` | файлы для скачивания (задания, справки, данные) |

Рекомендации по выбору: практика в shell → `terminal`; «агент пишет код, студент запускает» →
`ai_code_task`; web-инструмент лучше ссылки → `embed`; эксперименты с параметрами генерации →
`llm_playground`; раздаточные файлы → `resources`. Подробно — в `slides.md` (разделы по каждому типу).

## Общие правила занятия

1. Комиксы (`image_group`) ведут сюжет: завязка → теория → практика → развязка.
2. Теория компактна, опирается на лекции соответствующих курсов из `prepared/`.
3. Практика выполняется ЧЕРЕЗ АГЕНТА: студент описывает задачу словами, агент пишет/запускает код,
   студент проверяет результат. Напр., `ai_task_chat` с systemPrompt «Василич-5.7» как агент-исполнитель.
4. **Домашних заданий в курсе нет** — практика и активности выполняются в рамках занятия. Контрольные
   точки отдельно не обязательны: сами задания с проверкой (`ai_task_chat` + `checkPrompt` и т.п.) и есть
   контроль. Квизы (`quiz`) и открытые вопросы (`open_question`) — по необходимости.
5. Файлы занятия кладутся в `files/`, ссылки — в `links.md`, сценарий комикса — в `comic.md`.
6. **Короткие тексты.** Текст `rich_text`-слайда — не больше **100–150 слов**, одна мысль на слайд.
   Сложные концепции (механизмы, схемы, потоки данных) словами не расписываем — выносим на `video`,
   `image_group` или `image`. Код-блоки, таблицы, диаграммы и подписи за «слова» не считаются.
7. **Порядок объяснения: метафора → наглядность → формальность.** Сначала короткое введение текстом
   (пара слов, заводская метафора), затем `video`/`image_group`, показывающие механизм, и только потом —
   более формальное и подробное объяснение текстом. Формальное определение не идёт первым.
8. **Схемы и формулы прямо в тексте.** В `rich_text` разрешены **Mermaid-диаграммы** (код-блок
   ```` ```mermaid ````: flowchart, sequence и др.) для простых схем и процессов — это полноценная
   «наглядность», отдельную картинку/видео рисовать не обязательно. Формулы пишем **LaTeX** (рендер
   **KaTeX**), поддерживается и **MathML**. Тяжёлые анимации и потоки данных — по-прежнему на `video`.
