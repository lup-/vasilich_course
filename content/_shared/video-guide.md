# Видео: как генерируются ролики

> Руководство для агента: как писать программы-сценарии для `video`-слайдов.
> Язык роликов — русский (RU). Внешний стиль — из `comic-style.md`, персонажи — из `world-bible.md`.

## Принцип

Каждый видеоролик на слайде типа `video` — это **Python-программа (скрипт)**, которая генерирует видео.
Никаких готовых файлов вручную: агент пишет сценарий кодом, студент запускает и проверяет результат.
Отрендеренный файл загружается на платформу и указывается в поле `video_url` слайда.

## Два движка (когда какой)

| Тип ролика | Что это | Движок |
|---|---|---|
| **Технический** | Объяснение механизмов, диаграммы, графики, анимации алгоритмов, потоки данных, схемы | **Manim** (ManimCE) |
| **Любой другой** | Заставки, атмосферные сцены, «доска», комикс-анимация, не-техническая графика | **Доработанный pygame** |

Правило выбора простое: ролик объясняет технику/данные → Manim; ролик показывает мир, персонажей,
настроение или общую заставку → pygame. Технический ролик не должен быть «красивой картинкой ради
картинки» — он должен визуализировать учебное содержание (например, токенизацию, контекст, график метрик).

## Где лежат скрипты

```
content/sem<N>/NN-<slug>/videos/
├── README.md                     # список роликов занятия и как их запускать
├── manim/                        # технические ролики (ManimCE)
│   └── <nn>-<slug>.py
└── pygame/                       # остальные ролики (доработанный pygame)
    └── <nn>-<slug>.py
```

Имя файла — по слайду: номер и короткий слаг (например, `04-tokenizaciya.py`, `02-zastavka-zavod.py`).

## Общие правила скрипта

- Разрешение: **1920×1080** (или 1280×720), **30 fps**, длительность **примерно 20–120 секунд**
  (ориентир, не жёсткий лимит: длинные поясняющие вставки с паузами под чтение могут продлить ролик).
- Оформление — из `comic-style.md`: палитра (болотный/ржавый/пыльный/бежевый/оливковый + кислотно-зелёный
  люминофор, оранжевый огонь), чёрный контур, атмосфера разрухи, надписи заглавными русскими буквами.
- Текст в кадре — **рубленый шрифт без засечек**, реплики — **ЗАГЛАВНЫМИ**.
- Шрифт — системный/вшитый. **Внешние картинки и ассеты допустимы** (например, готовые PNG для
  демонстрации), но агент **обязан сообщать о них**: перечислить в `videos/README.md` (какие файлы,
  откуда взяты, для чего) и указывать пути в скрипте. Размещать внешние ассеты в папке занятия
  `videos/` (или `images/`), рядом со скриптом.
- **Детерминизм:** один и тот же скрипт при запуске даёт один и тот же ролик (фиксированный `seed`
  для случайности).
- Сюжет ролика — учебный и короткий: одна мысль на ролик.

## Ролики на Manim (технические)

- Класс-сцена наследует `Scene` (ManimCE). Внутри — анимации и тексты.
- Подходит для: токенизация, контекст и «окно» модели, вероятностная генерация, сравнение моделей,
  графики и метрики, схема агента, потоки данных, конвейеры.
- Отрендеренный файл (MP4) должен соответствовать слайду `video` и встраиваться как `video_type: direct`.

## Ролики на pygame (не-технические)

- Используется **доработанный pygame**-движок (общие хелперы: персонажи, диалоговые облака с пилообразными
  краями, панели, фоны). Движок рисует сцену кадр за кадром и сохраняет видео.
- Подходит для: заставки занятия, атмосферные планы завода и аппаратной, «ожившие» комикс-панели,
  крупные планы персонажей (Василич, «Электроник-84»), переходы между темами.
- Персонажи — строго по `world-bible.md` (Василич: ушанка, ватник, кибер-протезы рук и т.д.).

## Значки (SVG) в роликах

- **Библиотека значков** — общая для всех роликов: `content/_shared/assets/icons/`. Никаких лишних
  картинок в папке занятия: нужный значок берём отсюда.
- **Источник** — Tabler Icons (https://tabler.io/icons, лицензия MIT): скачиваем отдельный файл как
  **SVG**, имя файла — слаг иконки (например, `bulb.svg`, `school.svg`, `file-text.svg`).
- **Стили**: у каждой иконки есть два варианта — контурный (`outline`, по умолчанию) и залитый
  (**filled**). На тёмном фоне ролика заполненные смотрятся лучше — при необходимости берём `filled`.
- **Использование в Manim**: подключаем `SVGMobject(path)`, цвет задаём **в коде** из палитры
  `comic-style.md` (например, `icon.set_color(BEIGE)`), размер — `icon.scale(...)`. В сам SVG цвет
  не «запекаем», чтобы одна иконка подходила под любые акценты ролика.
- **Путь к файлу** из скрипта в `videos/manim/`:
  `os.path.join(os.path.dirname(__file__), "..", "..", "..", "..", "_shared", "assets", "icons", ...)`.
- **Проверка загрузки**: неудачная загрузка отдаёт страницу «404: Not Found» размером ~14 байт.
  Перед использованием убеждаемся, что файл не битый (нормальный SVG — от нескольких сотен байт);
  битые файлы удаляем. Подписи рядом со значком — заглавными, шрифт и палитра — из `comic-style.md`.

## Порядок работы агента

1. В `slides-plan.md` отметить слайды типа `video` и решить тип ролика (технический / не-технический).
2. Написать скрипт в `videos/manim/` или `videos/pygame/` (имя по слайду).
3. Заполнить `videos/README.md`: файл, движок, команда запуска, что показывает ролик.
4. Проверить, что скрипт запускается без ошибок (прогон рендера).
5. В `slides-plan.md` у слайда заполнить `video_url` (путь к отрендеренному файлу), `video_type: direct`
   и `description`.

## Карточки-пояснения (вставки внутрь ролика)

Когда нужно объяснить механизм в середине сцены без перегрузки кадра — используйте полноэкранную
вставку («карточку»):

1. Накрывается чёрным оверлеем весь кадр.
2. Текст печатается по глифам (LaggedStart, `lag_ratio=0.04`).
3. Пауза на чтение (~2 с).
4. Всё исчезает, сцена продолжается с места остановки.

Ограничения:
- ≤ 3–4 строки текста, одна мысль.
- Палитра из `comic-style.md` (заголовок — акцентный цвет, текст — бежевый/пыльный; в текущих
  роликах заголовки опускаются, оставляют только тело).
- Используется системный шрифт `DejaVu Sans` (или моноширинный `DejaVu Sans Mono` для кода/токенов).
- Увеличивает длительность ролика — учитывайте лимит 20–120 с.

Пример реализации — метод `_card` в `content/sem1/02-chto-u-nee-vnutri/videos/manim/06-rnn-i-transformer.py`
и `content/sem1/06-etiketki-i-knopki/videos/manim/06-vyzov-instrumentov.py`.

## Работа с правками ролика

- **Итерация правок:** после каждой правки скрипта агент **сам рендерит видео и копирует готовый MP4**
  в `videos/` (путь занятия, например `videos/05-chisla.mp4`). Рендер — это часть цикла правок, а не
  отдельный шаг.
- **Видео сам агент не проверяет.** Картинку, читаемость текста, наложения, темп, художественный результат
  смотрит **человек** (сквозная тема курса: не доверяй результату без проверки). После рендера и копирования
  агент просто сообщает, что ролик готов, и ждёт замечаний.
- Агент проверяет только то, что можно проверить расчётом и не «глазом»: запуск без ошибок, длительность,
  отсутствие падений (например, расчёт, что подписи не накладываются). Визуальные замечания — от человека.
