# Задание «Кнопка „склад“ и этикетки»

> Материал для `ai_code_task`-слайда 15 занятия 06. Краткая версия задания уже в `markdown` слайда;
> здесь — полный текст для человека, который проверяет работу, и детали для агента-исполнителя.
> Ответ на контрольный вопрос вводится на слайде 15 и проверяется автоматически по эталону (ниже).

## Суть

Одна задача в два шага. Через ИИ-агента собрать Python-скрипт, который:

1. **«Кнопка склад».** Через API OpenRouter и **вызов инструментов (tool calling)** отвечает на вопросы
   о реальных позициях склада: инструмент «склад»: `sklad(tovar)` по названию позиции
   возвращает карточку из `sklad.csv` (есть ли в наличии); модель сама решает, когда её вызвать;
   результат инструмента возвращается модели, и она отвечает по нему. Дополнительно — наивное сравнение:
   тот же вопрос **без** инструмента, чтобы увидеть, что модель отвечает «из головы».
2. **Этикетки.** Читает `sklad.csv` и генерирует этикетки для позиций **в наличии** через бесплатный
   сервис генерации изображений **без ключа** (например Pollinations.ai) в папку `etikety/`. На каждой
   этикетке — данные позиции по спецификации (см. ниже): масса мешка, для порошка — дозировка
   и мягкость воды, для цемента — марка.

Ответ сверяется с файлом склада, этикетки проверяются глазами. Задание можно сделать **на платформе
или в локальном opencode** (`@opencode-ustanovka`) — как удобнее.

## Что описать агенту (словами, код не писать)

1. **Инструмент «склад»:** `sklad(tovar)` — по названию позиции возвращает карточку из
   `sklad.csv` (папка задания): есть ли позиция в наличии и остаток (позиция с остатком 0 — «нет
   в наличии»). Описание инструмента — коротко: имя, параметр (название позиции), что делает.
2. **Цикл вызова:** модель получает вопрос → сама решает, что нужен инструмент «склад», формирует вызов
   с аргументом → программа выполняет инструмент (читает файл) → результат возвращается модели → модель
   отвечает по нему. Повторять, пока модель не даст финальный ответ.
3. **Контрольный вопрос:** чтобы ответить «Какие позиции есть на складе?», модель проверяет по одной
   каждую позицию ассортимента завода (порошок стиральный, сода, цемент, сахар) и собирает ответ из
   карточек. Позиция с остатком 0 (сахар) в список не входит — в наличии её нет.
4. **Наивное сравнение:** тот же вопрос через ту же модель **без** инструмента — ответ «из головы»
   (модель может назвать позиции, которых нет, например «найти» сахар).
5. **Этикетки:** читать `sklad.csv` (позиция; количество; единица) — генерируем этикетки для позиций,
   которые есть **в наличии** (остаток больше 0). У сахара остаток 0 — в наличии его нет, этикетку
   не делаем (нечего везти в магазины). Промпт на каждую позицию: название (например
   «ПОРОШОК-МАКС»), назначение (стиральный порошок / чистящая сода / строительный цемент),
   данные позиции по спецификации (см. ниже), завод «БытХимИскИнДеталь», стиль старых советских
   плакатов, болотно-ржавая палитра, размер квадратный (1024×1024, если сервис позволяет), ничего
   опасного и взрослого. Сохранять всё в папку `etikety/` с именами по позиции (например
   `poroshok-maks.png`) и выводить список сохранённых файлов.
6. **Секреты:** ключ OpenRouter — только в `.env`; файл `.env.example` с пустым ключом; `.env`
   не показывать. Для генерации этикеток ключ не нужен — сервис бесплатный и публичный, в него уходят
   только названия товаров (приватность: никаких личных данных и секретов).
7. **Проверка:** выводить и ответ с инструментом (со ссылкой на реальный список), и ответ без инструмента,
   чтобы их можно было сравнить, и список сохранённых этикеток.

## Спецификация этикетки

Этикетка — не только название: на ней данные позиции, чтобы в магазине было видно, что в мешке.
Общие поля: название позиции, назначение, завод «БытХимИскИнДеталь», стиль советских плакатов,
болотно-ржавая палитра, квадрат 1024×1024, ничего опасного и взрослого. Та же спецификация — на слайде 6
(`files/zadanie-etiketka.md`).

| Позиция | Обязательные данные |
|---|---|
| «ПОРОШОК-МАКС» (стиральный порошок) | масса мешка **25 кг**, дозировка **«100 г на стирку»**, **«для жёсткой и мягкой воды»** |
| «СОДА-ЭКСТРА» (чистящая сода) | масса мешка **20 кг** |
| «ЦЕМЕНТ-84» (строительный цемент) | масса мешка **50 кг**, марка **М500** |

Текста на этикетке много — числа и надписи будут «плыть» чаще названия, поэтому проверка глазами
обязательна.

## Требования к коду (что должен сделать агент)

- `sklad_agent.py` (или несколько файлов) — скрипт: описание инструмента «склад», цикл вызова через API
  OpenRouter, наивное сравнение без инструмента; генерация этикеток через бесплатный сервис без ключа
  (Pollinations.ai или альтернатива — проверить, что жив на момент запуска), сохранение в `etikety/`.
  Читает `sklad.csv` из папки задания.
- `requirements.txt`: `openai` (клиент для OpenRouter), `python-dotenv` (+ библиотека для HTTP-запросов
  к сервису картинок, если она ещё не в списке).
- `.env.example`: `OPENROUTER_API_KEY=`.
- Без жёстких ключей в коде. Модель — бесплатная с поддержкой tools: **не все бесплатные модели
  поддерживают вызов инструментов** — подобрать на момент сборки по каталогу/докам OpenRouter
  (https://openrouter.ai/collections/free-models) и зафиксировать в коде.

## Контрольный вопрос

> **«Какие позиции есть на складе?»**

Правильный ответ (эталон для проверки): **порошок стиральный, сода, цемент** (порядок не важен).
В `sklad.csv` есть ещё сахар — но с остатком 0, в наличии его нет, поэтому в ответ он не входит.
Инструмент «склад» должен вернуть карточки позиций из файла, а модель — собрать по ним ответ. Сверь ответ
с файлом (открой `sklad.csv`) и сравни с ответом модели **без** инструмента (та может «плыть» и «найти»
лишнее).

## Как проверить

1. Собрать файлы из ответа агента у себя на компьютере, создать `.env`, установить зависимости.
2. Запустить скрипт, задать контрольный вопрос.
3. Сверить список позиций с `sklad.csv` (порошок стиральный, сода, цемент; сахар — нет в наличии)
   и сравнить с ответом модели без инструмента.
4. Проверить, что в папке `etikety/` есть этикетки только для позиций в наличии (порошок, сода, цемент;
   позицию с остатком 0 — сахар — скрипт пропустил), и **проверить глазами каждую этикетку** — текст
   на картинках может «плыть», это нормально; подправить промпт и перегенерировать, где надо.
5. Убедиться, что в коде нет ключей (секреты — только в `.env`).
6. Ввести ответ на слайде 15 — он проверится автоматически.
