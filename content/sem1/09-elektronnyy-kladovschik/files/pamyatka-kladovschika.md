# Памятка «Электронный кладовщик»

> Шпаргалка к занятию 09. Рецепт прикладного промпта кладовщика и все приёмы занятия. Бриф главной практики — в `zadanie-kladovschik.md`, база знаний — в `instrukciya-ceha.md`, заказы — в `zakazy-postavschikam.md`, накладные — в `pisma-postavschikov.md`. Кладовщик остаётся на складе до конца семестра (занятия 11–13, 15–16).

## Зачем это нужно

Электронный кладовщик — не «поговорить» с моделью, а прогнать **сквозной конвейер**: заказ из системы + накладная из почты → сверочная таблица → сверка с инструкцией цеха → ветвление: полное соответствие — письмо «заказ принят» и акт приёмки; недосдача или излишки — письмо поставщику о расхождении; вопрос вне инструкции — эскалация дежурному кладовщику. Модель — как новый сотрудник без опыта: без точного ТЗ выдаст «воду» и «наобум», с ТЗ — сделает как надо. Один конвейер работает на двух поставщиках без перенастройки — меняются только бумаги.

## Рецепт промпта кладовщика (5 ингредиентов + проверка)

1. **РОЛЬ** — как сотрудник: электронный кладовщик цеха №7.
2. **ЗАДАЧА** — что сделать: сверить накладную с заказом, сверь с инструкцией, оформить акт или письмо поставщику.
3. **КОНТЕКСТ** — данные: инструкция цеха + заказ из системы + накладная из почты — в метках START CONTEXT / END CONTEXT.
4. **ФОРМАТ ВЫВОДА** — сверочная таблица (Markdown/CSV), акт, письмо в 3 абзаца, список-чек-лист.
5. **ТОН / ОБЪЁМ** — строгий/деловой/тёплый, краткий/подробный.

Плюс **проверка**: таблицу сверяем с обеими бумагами (контрольные суммы), ответ — с инструкцией (п.4.2–4.5, 1.1–1.6).

```
РОЛЬ: Ты — электронный кладовщик цеха №7 завода «БытХимИскИнДеталь».
Отвечай только по документам из контекста. Если ответа нет в инструкции —
так и скажи и передай вопрос дежурному кладовщику (п.6.4).

START CONTEXT
…текст инструкции цеха…
END CONTEXT

START CONTEXT
…заказ №214 из системы…
END CONTEXT

START CONTEXT
…накладная из почты (сырой текст)…
END CONTEXT

Задача: сверь накладную с заказом по строкам, оформи результат.
```

## Приёмы по видам работы

### Письма-ответы (лекция `writing_emails`)

- Указываем **тип ответа** («заказ принят» / «расхождение»), тон (строгий / деловой / тёплый), структуру (приветствие, суть — что заказано/что поставлено/отклонения, что просим — допоставить или решить с излишками, подпись) и объём (3 абзаца).
- Одно и то же дело — разные письма: меняется только строка про тип и тон. Расхождение — тон строже; полное соответствие — деловой или тёплый.
- Перед отправкой читаем: факты и цифры проверяет человек.

### Таблицы (лекция `table_generation`)

- Две сырые/структурные бумаги → **сверочная таблица**: колонки наименование, заказано, поставлено, отклонение, сумма по накладной. Колонки и формат задаём в промпте.
- Контрольные суммы обязательны: ХимСнаб №214 — 108 900 = 108 900 руб (совпадает); СодаТрест №88 — заказ 73 000, накладная 71 300 руб (расхождение −1 700: недосдача −2 600, излишек +900). Модель может переврать цифры или «додумать» строку.
- Отличие от занятий 11–12: там таблицы уже готовые и их считает код pandas; здесь таблицу собирает LLM из бумаг.

### Чек-листы и акты (лекция `summarize`)

- Инструкция → чек-лист приёмки: формат («по шагам, без пояснений»), объём (5–7 пунктов), «что важно» (п.1.1–1.6: вызвать лаборанта и кладовщика, проверить документы, проверить бочки, отобрать пробу из 3 бочек, дождаться заключения, опломбировать и записать пломбу).
- Акт приёмки (п.4.4) и акт расхождения (п.4.3): номер заказа, таблица соответствия, вывод, место для подписей. Каждый пункт сверяем с инструкцией — модель может упустить шаг или «додумать» пункт.

### Ответ по документам — один набор бумаг в промпте (задание `build_chatbot_from_kb`)

- Промпт кладовщика = **роль + заказ + накладная + инструкция в метках START CONTEXT/END CONTEXT + задача**.
- Контраст с занятием 5 (RAG): там много документов через векторный поиск (эмбеддинги, топ-3 чанка); здесь — три коротких документа целиком в промпте, потому что они влезают в окно. Для длинных баз нужен поиск (занятие 5).
- Ответы — только из документов; вопрос вне инструкции — не выдумка и не молчание, а **эскалация**: честное «нет в инструкции» и передача вопроса дежурному кладовщику (п.6.4). Неоднозначный запрос — переспросить.

## Как проверять результат (главное!)

1. Сверяй таблицу с бумагами: каждую строку — и с заказом, и с накладной; ИТОГО с эталонами (108 900 / 71 300). Не сошлось — ищи ошибку модели.
2. Сверяй ответ с инструкцией: проценты расхождений и действия — с п.4.2–4.5, приёмку — с п.1.1–1.6, эскалацию — с п.6.4.
3. Экономика: три коротких документа в промпте — токены. Не кладём всю базу (занятие 8 — окно контекста).
4. Приватность: в промпты — только рабочие бумаги. Пароли, ключи, личные данные — никогда.
5. Модель быстрая и вежливая, но проверяет за неё человек — а за кладовщиком ещё и бухгалтерия, ждущая закрывающие документы. Таблицы кладовщика лягут в сводки занятий 11–12 и в итоговый отчёт занятия 16.
