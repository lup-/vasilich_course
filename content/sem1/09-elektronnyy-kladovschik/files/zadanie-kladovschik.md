# Задание «Кладовщик на смену»

> Главная контрольная точка занятия 09 (слайд 12). Выполняется на платформе: результат вставляется в чат `ai_task_chat`-слайда 12 и проверяется через `checkPrompt`. Материалы: `zakazy-postavschikam.md` (заказы из системы), `pisma-postavschikov.md` (накладные из почты), `instrukciya-ceha.md` (база знаний), `pamyatka-kladovschika.md` (рецепт). Кладовщик остаётся на складе до конца семестра — его таблицы и акты лягут в сводки занятий 11–12 и в отчёт занятия 16.

## Цель

Собрать сквозной конвейер электронного кладовщика — сверяет накладную реальной поставки с заказом в системе, проверяет приёмку по инструкции цеха и оформляет исход: письмо «заказ принят» + акт приёмки, либо письмо о расхождении — и прогнать его на двух поставщиках без перенастройки.

## Рецепт промпта кладовщика (собери из пяти ингредиентов)

```
РОЛЬ: Ты — электронный кладовщик цеха №7 завода «БытХимИскИнДеталь».
Отвечай только по документам из контекста. Если ответа нет в инструкции —
так и скажи и передай вопрос дежурному кладовщику (п.6.4). Неоднозначный
вопрос — уточни.

START CONTEXT
…текст из instrukciya-ceha.md…
END CONTEXT

START CONTEXT
…заказ №… из zakazy-postavschikam.md…
END CONTEXT

START CONTEXT
…накладная из pisma-postavschikov.md…
END CONTEXT

Задача: …
```

Инструкция, заказ и накладная короткие и целиком влезают в окно модели; для длинных баз пользовались бы поиском по смыслу, как в занятии 5 (RAG: много документов через эмбеддинги). В отличие от занятий 11–12, где таблицы уже готовые и их считает код pandas, здесь сверочную таблицу из бумаг собирает LLM.

## Две поставки для прогона

1. **ООО «ХимСнаб» — Накладная к заказу №214 от 15.07.2120** — 6 позиций, эталон **108 900 = 108 900 руб** (должно сойтись полностью).
2. **ООО «СодаТрест» — Накладная к заказу №88 от 18.07.2120** — 5 позиций, заказ **73 000 руб**, накладная **71 300 руб** (не сойдётся).

Заказы — в файле `zakazy-postavschikam.md` (структурно, таблицами), накладные — в `pisma-postavschikov.md` (сырой текст простынёй, всё в одну строку).

## Что сделать (конвейер на двух поставках)

Для каждой поставки:

1) **Сверочная таблица.** Разбери обе бумаги в Markdown-таблицу с колонками: наименование, заказано, поставлено, отклонение, сумма по накладной + строка ИТОГО. Сверь ИТОГО с эталоном (108 900 / 71 300). Если не сошлось — найди, какую строку модель переврала.

2) **Расхождения.** По каждой позиции посчитай отклонение `(поставлено − заказано) / заказано`. ХимСнаб №214 — всё по нулю; СодаТрест №88 — недосдача по соде кальцинированной (40 из 50 мешков, −2 600 руб, −20%) и излишек по соли технической (+5 мешков, +900 руб, ≈+11%). Оба отклонения больше 1% → по п.4.3 нужен акт расхождения, излишки — на ответственное хранение по п.4.5.

3) **Исход по инструкции.**
   - **ХимСнаб №214:** расхождений нет → письмо «заказ принят» (сумма 108 900, приёмка по чек-листу п.1.1–1.6) + **акт приёмки** — закрывающий документ для бухгалтерии (п.4.4).
   - **СодаТрест №88:** письмо о расхождении выбранным тоном (что заказано/что поставлено/отклонения в рублях и процентах, что просим: допоставить соду и решить судьбу излишка соли). Структура: приветствие, суть, что просим, подпись. Не больше 3 абзацев, факты — только из таблицы и инструкции.
   - Тона у двух писем разные (строгий/деловой/тёплый — на выбор, но два разных).

Дополнительно — один общий кейс:

4) **Вне инструкции — эскалация.** Спроси кладовщика: «Сколько бочек привезут в среду?» — в инструкции этого нет. Верный ответ: честное «нет в инструкции» **и передача вопроса дежурному кладовщику смены** (п.6.4), а не выдуманное число. Неоднозначный вопрос «Что делать с сырьём?» — должен уточнить, о каком сырье речь.

## Что вставить в чат (слайд 12)

1. Собранный промпт кладовщика (роль + инструкция + заказ + накладная в метках START/END CONTEXT + задача).
2. Две сверочные таблицы с ИТОГО + пометка «сошлось / не сошлось с эталоном».
3. Два письма-ответа (разными тонами) и акт приёмки по ХимСнабу.
4. Ответ на кейс вне инструкции (честный отказ + эскалация) и 2–3 строки выводов: где суммы сошлись, где модель пыталась выдумать, с чем сверял. Нажми «Проверить».

## Как проверяется

`checkPrompt` оценивает: собран ли промпт по рецепту (роль кладовщика + инструкция + заказ + накладная в метках START CONTEXT/END CONTEXT + задача); собраны ли две сверочные таблицы (наименование, заказано, поставлено, отклонение, сумма) с ИТОГО 108 900 и 71 300, сверенными с эталонами; найдены ли расхождения СодаТреста (недосдача −20%, излишек ≈+11%, оба >1% → п.4.3); оформлены ли письмо «заказ принят» + акт приёмки (п.4.4) по ХимСнабу и письмо о расхождении по СодаТресту — разными тонами, до 3 абзацев, с отсылкой к таблице и инструкции; кейс вне инструкции — честное «нет в инструкции» + эскалация дежурному кладовщику (п.6.4), а не выдумка; есть ли выводы про проверку. Таблицы и акты кладовщика пригодятся в занятиях 11–13 и 16.

## Чего не делаем

- Не кладём в промпт пароли, ключи и личные данные (приватность) — только заказы, накладные и инструкцию.
- Не доверяем «красивому ответу» без сверки: таблицу — с обеими бумагами (контрольные суммы), действия — с инструкцией.
- Не подписываем акт и не отправляем письмо без проверки человеком: кладовщик готовит бумаги, решение принимает человек.
- Не таскаем в каждый запрос всю базу знаний целиком: три коротких документа в промпте (занятие 9) vs много документов через поиск (занятие 5, RAG) — длинный контекст = токены = деньги.
