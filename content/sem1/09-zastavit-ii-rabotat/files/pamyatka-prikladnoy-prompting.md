# Памятка «Прикладной промптинг»

> Шпаргалка к занятию 09. Рецепт прикладного промпта и все приёмы занятия. Бриф главной практики —
> в `zadanie-instrumenty-smeny.md`, база знаний — в `instrukciya-ceha.md`.

## Зачем это нужно

Прикладной промптинг — это не «поговорить» с моделью, а получить **готовый рабочий артефакт**: письмо,
таблицу, памятку, дежурного по инструкциям. Модель — как новый сотрудник без опыта: без точного ТЗ выдаст
«воду» и «наобум», с ТЗ — сделает как надо.

## Рецепт прикладного промпта (5 ингредиентов)

1. **РОЛЬ** — как сотрудник: технолог цеха, снабженец, методист.
2. **ЗАДАЧА** — что сделать: написать, разложить, составить.
3. **КОНТЕКСТ** — данные: вставляем документ, цифры, факты (метки START CONTEXT / END CONTEXT).
4. **ФОРМАТ ВЫВОДА** — таблица, 3 абзаца, Markdown, список.
5. **ТОН / ОБЪЁМ** — строгий/деловой/тёплый, краткий/подробный.

Плюс **проверка**: результат сверяем с исходными документами.

## Приёмы по видам работы

### Письма (лекция `writing_emails`)

- Указываем тон (строгий / деловой / тёплый), структуру (приветствие, суть, что просим, подпись) и объём.
- Одно и то же дело — три разных письма: меняется только строка про тон.
- Перед отправкой читаем: факты и цифры проверяет человек.

### Сводки (лекция `summarize`)

- Задаём объём, аудиторию и «что важно»: «сократи до 5 пунктов для новой смены, только что делать».
- Можно попросить оглавление — быстро понять структуру текста.
- Сводку сверяем с исходником: модель может упустить важное или «додумать» деталь.

### Таблицы (лекция `table_generation`)

- Сырой текст → таблица: задаём колонки и формат (Markdown/CSV), сумму считает модель.
- Контрольная сумма обязательна: модель может переврать цифры или «додумать» строку.

### Памятки и чек-листы (лекция `summarize`)

- Инструкция → памятка-чек-лист: задаём формат («по шагам, без пояснений»), объём (5–7 пунктов)
  и «что важно».
- Это сводка в виде готовых шагов для работы (см. «Сводки» выше).
- Каждый пункт памятки сверяем с инструкцией: модель может упустить шаг или «додумать» пункт.

### Чат-бот на базе знаний (задание `build_chatbot_from_kb`)

- Промпт = **роль + контекст (документ в метках START CONTEXT/END CONTEXT) + история диалога + вопрос**.
- Ответы — из контекста; вопрос вне контекста — модель честно говорит «не знаю», а не выдумывает.
- Неоднозначный вопрос — модель переспрашивает (уточнение).
- Риск: если в контексте ответа нет, модель может «додумать» (занятие 3) — проверяем.

## Как проверять результат (главное!)

1. Сверяй с исходником: письмо — с фактами заказа, таблицу — с накладной (контрольная сумма), памятку —
   с инструкцией, ответы дежурного — с документом из базы.
2. Экономика: длинный контекст — токены. В промпт кладём только нужный документ, а не всю базу
   (занятие 8: длинный текст — не всё сразу).
3. Приватность: в промпты — только рабочие данные. Пароли, ключи, личные данные — никогда.
4. Модель быстрая и вежливая, но проверяет за неё человек.
