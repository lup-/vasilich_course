# Задание «Диспетчер на дежурство»

> Главная контрольная точка занятия 09 (слайд 17). Выполняется на платформе: результат вставляется
> в чат `ai_task_chat`-слайда 17 и проверяется через `checkPrompt`. Материалы: `instrukciya-ceha.md`
> (база знаний), `pamyatka-prikladnoy-prompting.md` (рецепт промпта).

## Цель

Собрать через агента чат-бота на базе знаний — «дежурного по инструкциям цеха» — и проверить, что он
отвечает только по документу из базы, а не выдумывает.

## Рецепт промпта дежурного (собери из пяти ингредиентов)

```
РОЛЬ: Ты — дежурный по инструкциям цеха №7 завода «БытХимИскИнДеталь».
Отвечай только по документу из базы знаний. Если в документе ответа нет —
так и скажи: «Не знаю, в инструкции нет». При неоднозначном вопросе — уточни.

START CONTEXT
…текст из instrukciya-ceha.md…
END CONTEXT

Вопрос: …
```

Документ в промпт вставляем целиком из `instrukciya-ceha.md` (он короткий и в «окно» модели помещается;
для более длинных баз пользовались бы поиском по смыслу, как в занятии 5).

## Три кейса для проверки

1. **По инструкции.** Спроси: «Как принять партию глицерина?» — ответ должен опираться на пункты 1.1–1.6
   инструкции (вызвать лаборанта и кладовщика, проверить документы и бочки, отобрать пробу и т.д.).
2. **Вне инструкции.** Спроси: «Сколько бочек глицерина привезут в среду?» — в инструкции этого нет.
   Дежурный должен честно сказать, что не знает, а не выдумать число.
3. **Неоднозначный вопрос.** Спроси: «Что делать с сырьём?» — в инструкции несколько разделов про разное
   сырьё. Дежурный должен уточнить, о каком сырье речь (или о какой ситуации).

## Что вставить в чат (слайд 17)

1. Собранный промпт дежурного.
2. Ответы на три кейса (по инструкции / вне инструкции / неоднозначный).
3. 2–3 строки выводов: где ответ был из контекста, где модель попыталась выдумать, что ты сделал
   и с чем сверял результат.

## Как проверяется

`checkPrompt` оценивает: собран ли промпт по рецепту (роль + контекст в метках START CONTEXT/END CONTEXT +
вопрос); протестированы ли три кейса; в кейсе «вне инструкции» дежурный честно отказался, а не выдумал;
в неоднозначном кейсе — переспросил; есть ли выводы про проверку результата.

## Чего не делаем

- Не кладём в промпт пароли, ключи и личные данные (приватность) — только инструкцию цеха.
- Не доверяем «красивому ответу» без сверки с документом: модель может «додумать» (занятие 3).
- Не таскаем в каждый запрос всю базу знаний целиком: длинный контекст — это токены (экономика).
