## Зачем это нужно

Прикладной промптинг — это не «поговорить» с моделью, а получить **готовый рабочий артефакт**: письмо,
сводку, таблицу, памятку, дежурного по инструкциям. Модель — как новый сотрудник без опыта: без точного ТЗ
выдаст «воду» и «наобум», с ТЗ — сделает как надо.

## Рецепт прикладного промпта (5 ингредиентов)

1. **РОЛЬ** — как сотрудник: технолог цеха, снабженец, методист.
2. **ЗАДАЧА** — что сделать: написать, разложить, составить.
3. **КОНТЕКСТ** — данные: вставляем документ, цифры, факты (метки START CONTEXT / END CONTEXT).
4. **ФОРМАТ ВЫВОДА** — таблица, 3 абзаца, Markdown, список.
5. **ТОН / ОБЪЁМ** — строгий/деловой/тёплый, краткий/подробный.

Плюс **проверка**: результат сверяем с исходными документами.

## Письма

Указываем тон (строгий / деловой / тёплый), структуру (приветствие, суть, что просим, подпись) и объём.
Одно и то же дело — три разных письма: меняется только строка про тон. Ответ на длинное письмо можно
начать с поручения «сделай сводку и список задач» — и писать ответ по сводке. Перед отправкой письмо
читаем: факты и цифры проверяет человек.

## Сводки

Задаём объём, аудиторию и «что важно»: «сократи до 5 пунктов для новой смены, только что делать».
Можно попросить оглавление — быстро понять структуру текста, не читая всё. Продолжение темы «длинный
текст» занятия 8. Сводку сверяем с исходником.

## Таблицы

Сырой текст (накладная, отчёт) → таблица: задаём колонки и формат (Markdown/CSV), сумму считает модель.
Основа для Excel, баз данных и отчётов (задел на занятия 11–12). Контрольная сумма обязательна: модель
может переврать цифры или «додумать» строку.

## Памятки и чек-листы

Инструкция → памятка-чек-лист для смены: задаём формат («только действия, по шагам, без пояснений»),
объём (5–7 пунктов) и «что важно». Это сводка (см. выше) в виде готовых шагов для работы. Экономия времени:
вместо перечитывания длинной инструкции — листок с действиями. Каждый пункт памятки сверяем с инструкцией:
модель может упустить шаг или «додумать» пункт.

## Написание кода

Модель пишет и код — это весь курс: студент описывает задачу словами, агент пишет и запускает код,
студент проверяет результат (см. занятия 5–8). Код из модели — это тоже прикладной промптинг:
роль + задача + контекст + формат (язык, стиль) + проверка запуском.

## Чат-бот на базе знаний (дежурный по инструкциям)

Промпт = **роль + контекст (документ в метках START CONTEXT/END CONTEXT) + история диалога + вопрос**.

```text
Ты — дежурный по инструкциям цеха №7. Отвечай только по документу из базы.
Если в документе ответа нет — скажи: «Не знаю, в инструкции нет».

START CONTEXT
…документ из базы знаний…
END CONTEXT

Вопрос: …
```

Что это даёт:

- **Ответы — из контекста.** Вопрос по документу — модель отвечает по нему, точно.
- **Вне контекста — не выдумывать.** Спросили не по теме — модель честно «не знаю», а не «додумывает»
  (это галлюцинации, занятие 3).
- **Уточняющий вопрос.** Неоднозначный запрос — модель переспрашивает, как опытный диспетчер.
- **Память диалога.** История переписки добавляется в промпт, чтобы отвечать с учётом контекста
  (занятие 4).

Почему не вся база сразу: у модели ограниченное «окно» (занятие 8). Для длинных баз нужен поиск по
смыслу — это уже было в занятии 5 (семантический поиск/RAG). Секреты в промпты не кладём (приватность).

## Правила

1. **Проверяй.** Письмо — с фактами заказа; таблицу — с накладной (контрольная сумма); памятку — с
   инструкцией; ответы дежурного — с документом из базы.
2. **Считай токены.** Длинный контекст — это токены: в промпт кладём только нужный документ, а не всё.
3. **Без секретов.** В промпты — только рабочие данные: никаких паролей, ключей и личных данных.
