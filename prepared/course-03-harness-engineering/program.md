# Программа курса: Learn Harness Engineering (Инженерия агентных harness)
> Оригинал: [walkinglabs/learn-harness-engineering](https://github.com/walkinglabs/learn-harness-engineering). Контент подготовлен на основе официального русского перевода (`docs/ru`). Язык: русский (RU).

## О курсе
Курс об инженерии AI-агентов для кодинга. На основе практик OpenAI (Codex), Anthropic (Claude Code) и сообщества курс учит системному проектированию окружения, управлению состоянием, верификации и контролю, чтобы сделать агентские инструменты по-настоящему надёжными: строить фичи, чинить баги и автоматизировать задачи, ограничивая агента явными правилами и границами.

## Для кого
Курс для: инженеров, уже использующих кодинг-агентов; исследователей и разработчиков, которым нужно системное понимание дизайна harness; техлидов, которым важно, как окружение влияет на работу агентов. Не подходит тем, кто ищет введение в ИИ без кода или не готов запускать агентов в реальных репозиториях.

## Предварительные требования
- уверенная работа с терминалом, git и локальной средой разработки;
- умение писать и читать код в хотя бы одном стеке;
- базовый опыт отладки (логи, тесты, поведение рантайма);
- как минимум один кодинг-агент: Claude Code, Codex или аналогичный.

## Структура курса: лекции (13)
| № | Вопрос | Основная идея |
|---|---|---|
| L01 | Почему сильные модели всё равно ошибаются на реальных задачах? | Разрыв между бенчмарками и реальной инженерией |
| L02 | Что на самом деле означает «harness»? | Пять подсистем: инструкции, состояние, верификация, скоуп, жизненный цикл |
| L03 | Почему репозиторий должен быть единственным источником истины? | Если агент не может это увидеть — этого не существует |
| L04 | Почему один гигантский файл инструкций не работает? | Прогрессивное раскрытие: дайте карту, а не энциклопедию |
| L05 | Почему долгие задачи теряют непрерывность? | Сохраняйте прогресс на диск; продолжайте с места остановки |
| L06 | Почему инициализация должна быть отдельной фазой? | Проверяйте здоровье окружения до начала работы агента |
| L07 | Почему агенты выходят за рамки и недоделывают? | Одна фича за раз; явное определение готовности |
| L08 | Почему списки фич — примитивы harness? | Машиночитаемые границы скоупа, которые агент не может игнорировать |
| L09 | Почему агенты слишком рано заявляют о победе? | Пробелы верификации: уверенность ≠ корректность |
| L10 | Почему сквозное тестирование меняет результат? | Реальная верификация — только полный прогон пайплайна |
| L11 | Почему наблюдаемость должна быть внутри harness? | Не видно, что агент сделал — не починить, что он сломал |
| L12 | Почему каждая сессия должна оставлять чистое состояние? | Успех следующей сессии зависит от уборки текущей |
| L13 | Почему нужно перестать промптить агента вручную? | От ручного управления к автономным циклам: goal-циклы, timer-циклы, разделение maker/checker |

Лекции: `lectures/lecture-NN-<slug>.md`, примеры кода — `code/<slug>/`.

## Структура курса: проекты (7)
| № | Что вы делаете | Механизм harness |
|---|---|---|
| P01 | Одна и та же задача дважды: только промпт vs. правила в первую очередь | Минимальный harness: AGENTS.md + init.sh + feature_list.json |
| P02 | Перестройте репозиторий так, чтобы агент мог его читать | Агент-читаемый воркспейс + персистентные файлы состояния |
| P03 | Заставьте агента продолжать с места остановки | Журнал прогресса + handoff + межсессионная непрерывность |
| P04 | Не дайте агенту делать слишком много или слишком мало | Runtime-обратная связь + контроль скоупа + инкрементальная индексация |
| P05 | Заставьте агента проверять свою работу | Самопроверка + grounded Q&A + завершение на основе доказательств |
| P06 | Постройте полный harness с нуля (capstone) | Полный harness: все механизмы + наблюдаемость + абляционное исследование |
| P07 | Постройте свой первый автоматический цикл | Goal-циклы, timer-циклы, разделение maker/checker, управление состоянием цикла |

Задания: `assignments/project-NN-<slug>.md`. Решение каждого проекта становится стартовой точкой следующего; приложение (база знаний на Electron) эволюционирует вместе с вашими навыками.

## Библиотека ресурсов (`resources/`)
- `templates/` — готовые шаблоны: AGENTS.md, CLAUDE.md, feature_list.json, init.sh, чек-листы;
- `reference/` — справочники методов: method-map, prompt-calibration, agent-playbook и др.;
- `openai-advanced/` — расширенный репозиторий-шаблон и SOP по методологии OpenAI;
- `skills.md` — встроенные скилы (harness-creator).

## Как использовать подготовленную папку
- `program.md` — настоящая программа курса;
- `lectures/` — 13 лекций в Markdown;
- `assignments/` — 7 практических проектов;
- `code/` — примеры кода к лекциям;
- `resources/` — шаблоны и справочники.

## Продолжительность
13 лекций + 7 проектов; ориентировочно 8–12 недель при погружении в проекты.
