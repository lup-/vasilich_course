# 06. MCP: Model Context Protocol

> Семестр: 2 · Курс: «ИИ-агенты и протокол MCP» (course-06) · Время: ~3 часа

## Введение

Проблема: у каждого агента свой набор инструментов. Хотите дать агенту новый инструмент — приходится «настраивать» его по-своему. **MCP (Model Context Protocol)** — открытый стандарт, который решает это: один раз подключив инструмент (сервер MCP), вы даёте его любому совместимому агенту (клиенту MCP).

## Идея MCP

MCP — это протокол «как инструменты общаются с агентами». По аналогии:

- **USB** — единый разъём для разных устройств;
- **MCP** — единый «разъём» для подключения инструментов к ИИ.

Ключевые понятия:

- **MCP-клиент** — агент или интерфейс, который подключает инструменты (Gemini CLI, Claude, Open WebUI и др.);
- **MCP-сервер** — программа, которая предоставляет инструменты и данные (доступ к файлам, браузер, поиск, свои функции);
- **Инструменты** — функции, которые сервер отдаёт клиенту.

Один сервер можно подключить к разным клиентам — инструменты «переезжают» между агентами без переписывания.

## Зачем это вам

1. **Расширение агента**: хотите, чтобы агент работал с вашей базой, почтой, документами — находите/пишете сервер MCP и подключаете.
2. **Стандарт вместо кустарщины**: не «прикручивать» инструмент к каждому агенту отдельно.
3. **Данные вместо текста**: агент получает доступ к настоящим данным (файлы, БД, сайты), а не «представляет» их.
4. **Готовые серверы**: множество уже существует — от доступа к файлам и браузеру до Git и баз данных.

## Как это выглядит на практике

Схема работы:

```
вы → агент (клиент MCP) → сервер MCP → файлы/браузер/API
                              ↑
                    агент получает инструменты от сервера
```

Пример: вы подключаете к Gemini CLI сервер «файлы». Теперь агент может «попросить» сервер прочитать файл — и получить реальное содержимое. Без MCP пришлось бы встраивать это в сам агент.

## Какие серверы бывают

| Сервер MCP | Что даёт агенту |
|---|---|
| Файлы | читать/писать файлы и папки |
| Браузер | открывать страницы, собирать данные с сайтов |
| Поиск | искать в интернете |
| Git | работать с репозиториями |
| База данных | запросы к SQL-базам |
| Свои серверы | ваши функции и данные (лекция 08) |

Настройка готовых серверов — в лекции 07. Создание своего — в лекции 08.

## Клиенты MCP

MCP поддерживают (в разной степени): Gemini CLI, Claude Desktop, Open WebUI, ряд IDE и фреймворков. Для курса главный клиент — **Gemini CLI** (бесплатный, простой).

Проверить, что ваш агент поддерживает MCP:

> «Ты умеешь подключать MCP-серверы? Покажи, как это делается в твоей версии.»

## Практическая ценность для курса

MCP — ключ к «расширению» агента под реальные задачи:

- подключить файловый сервер → агент видит вашу папку с данными;
- подключить браузер → агент собирает данные с сайтов (лекция 09);
- написать свой сервер → агент вызывает ваши функции (лекция 08).

Это и есть путь от «чат-бота» к «работнику», который делает вашу работу.

## Частые проблемы

| Проблема | Решение |
|---|---|
| Агент не видит сервер | Проверить настройку клиента (лекция 07), перезапустить |
| Сервер не найден | Проверить имя и команду запуска |
| Нет доступа к файлам | Настроить права/пути сервера |
| Слишком сложно | Начать с одного готового сервера (файлы), потом расширять |
