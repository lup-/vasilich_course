> Семестр: 2 · Курс: «Локальные ИИ-модели и приватность» (course-07) · Время: ~3 часа

## Введение

В курсе-06 мы собирали агентов. До сих пор агенты чаще всего работали на облачных моделях. Теперь соединим: **агент на локальной модели** — данные не уходят из компьютера, а всё из курса-06 работает.

<!-- изображение (не скопировано): схема: агент → локальная модель (Ollama) → инструменты → результат -->

## Идея

Агент состоит из модели + инструментов. Модель можно заменить на локальную: фреймворки агентов (OpenAI Agents SDK, Gemini CLI) умеют подключаться к локальным серверам (Ollama, LM Studio).

```
ваш агент → локальная модель (Ollama) → инструменты (файлы, MCP)
                 (без отправки данных в облако)
```

Плюсы: приватность, работа офлайн, экономия на API. Минусы: локальные модели «слабее» топовых облачных — сложные задачи могут решаться хуже.

## Вариант 1: Gemini CLI на локальной модели

Gemini CLI можно настроить на работу с локальным сервером вместо облачного. Обычно это делается конфигом в переменных окружения (адрес сервера + имя модели). Точный способ зависит от версии — сверяйтесь с документацией или спросите агента:

> «Как в моей версии Gemini CLI подключить локальную модель через Ollama вместо облачной? Покажи точные настройки.»

## Вариант 2: OpenAI Agents SDK на локальной модели

Библиотека `openai-agents` умеет работать с любым сервером, совместимым с API OpenAI. Ollama и LM Studio предоставляют такой совместимый адрес. Пример настройки (через переменную окружения):

```bash
# адрес локального сервера и имя модели
export OPENAI_BASE_URL="http://localhost:11434/v1"
export OPENAI_API_KEY="ollama"   # локальный ключ, не секрет
export OPENAI_MODEL="qwen2.5:3b"
```

Тогда код из лекции 05 курса-06 заработает на локальной модели:

```python
from agents import Agent, Runner

agent = Agent(
    name="Локальный помощник",
    instructions="Ты — помощник. Отвечай кратко.",
)
result = Runner.run_sync(agent, "Расскажи, кто ты.")
print(result.final_output)
```

## Проверка, что работает локально

Признаки того, что агент использует локальную модель:
- в выводе нет запросов в облако (трафик не растёт);
- ответ приходит даже при выключенном интернете;
- в `ollama ps` видно, что модель запущена;
- скорость и качество соответствуют локальной модели.

## Ограничения

- Локальные модели хуже в сложных рассуждениях — для точных задач выбирайте модель побольше (лекция 03) или облачную.
- Медленнее (без хорошего GPU).
- Не все функции фреймворков поддерживаются локальными серверами одинаково хорошо.

## Когда это оправдано

- данные секретные и нельзя отправлять в облако;
- нет стабильного интернета;
- хочется экономить при большой нагрузке;
- в учебных/тренировочных целях (бесплатно и безопасно).

## Частые проблемы

| Проблема | Решение |
|---|---|
| Агент всё равно идёт в облако | Проверить переменные окружения (base_url) |
| Ошибка подключения | Ollama запущена? адрес/порт верный? `ollama list` |
| Локальная модель «не тянет» задачу | Взять модель больше/качественнее или облачную |
| Медленно | Меньше модель, GPU, квантование |
