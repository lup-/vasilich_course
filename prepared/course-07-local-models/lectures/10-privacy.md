# 10. Приватность: где ваши данные

> Семестр: 2 · Курс: «Локальные ИИ-модели и приватность» (course-07) · Время: ~2 часа

## Введение

Каждый раз, когда вы отправляете текст в облачный ИИ, копия этого текста появляется на чужих серверах. Разберём, какие есть риски, как их снизить и почему локальные модели — главный инструмент приватности.

## Что происходит с данными в облаке

1. Вы вводите текст/файл.
2. Он отправляется по интернету на сервер компании.
3. Сервер обрабатывает запрос (модель отвечает).
4. **Следы остаются**: компания может хранить запросы, использовать для «улучшения» сервиса, передавать по законам своей страны.

Даже если компания «не хранит» данные — технически они **проходят через её инфраструктуру**. Для многих данных этого уже достаточно, чтобы запретить использование.

## Какие данные нельзя отправлять в облако

- коммерческая тайна и документы компании;
- персональные данные (ФИО, адреса, телефоны, паспорта);
- медицинская и финансовая информация;
- переписка и личные файлы;
- любые данные, для которых есть требование «не передавать третьим лицам».

Если вы не уверены — считайте, что отправлять нельзя.

## Риски облачного использования

1. **Хранение запросов**: компания может сохранить ваш текст.
2. **Использование для обучения**: запросы могут попасть в обучающие данные (зависит от правил сервиса).
3. **Передача третьим лицам**: по запросу органов или подрядчикам.
4. **Утечки**: чужие серверы взламывают.
5. **Юридические риски**: компания обязана соблюдать законы своей юрисдикции.

## Как снизить риски (если облако необходимо)

- не отправляйте секреты (личные данные, пароли, документы);
- используйте тарифы/режимы «не сохранять» (если есть);
- очищайте тексты от идентифицирующей информации;
- читайте условия использования;
- по возможности — локальная модель.

## Локальная модель как решение

Локальная модель обрабатывает данные **на вашем компьютере**:

- данные не покидают устройство;
- нет хранения на чужих серверах;
- нет передачи третьим лицам;
- работает без интернета.

Именно поэтому для секретных данных локальный запуск — правильный (часто единственный допустимый) вариант. Всё, чему учит этот курс, работает на приватность.

## Дополнительные меры приватности

Даже с локальной моделью следите за:

1. **Файлами**: не оставляйте копии секретов в открытых папках.
2. **Паролями**: не просите модель «вспомнить» пароль; храните секреты отдельно.
3. **Обновлениями**: обновляйте программы (Ollama, Open WebUI) — закрывают уязвимости.
4. **Доступом**: настраивайте аккаунты Open WebUI (пароль на интерфейс).
5. **Удалением**: удаляйте неиспользуемые модели/чаты с секретами.

## Проверка перед отправкой (чек-лист)

Прежде чем «спросить модель» о данных, ответьте:

- [ ] Это мои данные или чужие?
- [ ] Есть ли запрет передавать их третьим лицам?
- [ ] Устраивает ли меня хранение копии на сервере компании?
- [ ] Есть ли локальная альтернатива?

Если хоть один ответ «да» на первые три или «да» на четвёртый — работайте локально.

## Частые проблемы

| Проблема | Решение |
|---|---|
| «Но мне удобно в облаке» | Использовать локальную модель для секретного, облако — для простого |
| «Компания говорит „нельзя облако“» | Локальные модели — решение, этот курс это умеет |
| «Локальная модель слабее» | Приватность важнее качества для секретных данных |
| Не знаю, что разрешено | Политика организации; если сомневаетесь — локально |
