# 11. Экономика локального ИИ

> Семестр: 2 · Курс: «Локальные ИИ-модели и приватность» (course-07) · Время: ~2 часа

## Введение

Стоит ли переходить на локальные модели? Ответ — в цифрах. Соберём простую модель расчёта: стоимость облака, стоимость локального запуска, точка окупаемости. Это сквозная тема программы «экономика/оценка».

<!-- изображение (не скопировано): график: расходы на облако растут с объёмом, локальные — почти константа; точка пересечения -->

## Из чего складывается стоимость облака

Облачные модели оплачиваются за использование: токены входящие/исходящие, либо подписка. Основной параметр — **объём использования**:

- сколько запросов в день/месяц;
- длина запросов и ответов (токены);
- тариф модели.

Прирост расхода примерно пропорционален объёму: больше запросов → дороже.

## Из чего складывается стоимость локального запуска

- **Железо**: если компьютер уже есть — 0 рублей; если покупать под модель — разовая стоимость.
- **Электроэнергия**: потребление компьютера во время работы модели.
- **Поддержка/время**: время на установку и обслуживание (можно учесть в часах × ставка).

После установки каждая дополнительная «единица» запросов почти бесплатна — поэтому при большом объёме локально выгодно.

## Простая модель расчёта

Соберём таблицу в Python (вместе с агентом):

```python
# Параметры
requests_per_day = 50
days_per_month = 22
months_per_year = 12

# Облако: стоимость одного запроса, руб.
cloud_cost_per_request = 0.5
cloud_year = requests_per_day * days_per_month * months_per_year * cloud_cost_per_request

# Локально: электроэнергия, руб./мес. (пример)
local_power_month = 200
local_year = local_power_month * months_per_year

# Оборудование (если покупали под задачу; если есть — 0)
hardware_once = 0

print(f"Облако за год: {cloud_year:,.0f} руб.")
print(f"Локально за год: {local_year + hardware_once:,.0f} руб.")
print(f"Разница: {cloud_year - (local_year + hardware_once):,.0f} руб.")
```

Подставьте свои числа — получите ответ для вашего случая.

## Что учитывать ещё (важные нюансы)

1. **Качество**: если локальная модель хуже и это стоит времени людей — учтите.
2. **Время**: скорость ответов влияет на продуктивность.
3. **Приватность**: у облака могут быть штрафы за утечку — это тоже стоимость (риск).
4. **Масштаб**: при росте запросов облако дорожает, локально — почти нет.
5. **Обновления**: облачные модели всегда последние; локальные — обновляете сами.

## Примеры

**Пример 1. Маленькая нагрузка (10 запросов/день).**
Облако: ~13 000 руб./год. Локально: электроэнергия ~2 400 руб./год + установка (если есть компьютер — 0). Вывод: локально заметно дешевле, если качество устраивает.

**Пример 2. Большая нагрузка (500 запросов/день).**
Облако: ~660 000 руб./год. Локально: компьютер под модель (разово) + электроэнергия. Вывод: локально почти всегда выгоднее.

**Пример 3. Слабый компьютер, нужна мощная модель.**
Локально не потянуть → облако (или покупка компьютера, тогда считать окупаемость).

## Точка окупаемости

Точка окупаемости — момент, когда накопленная экономия от локального запуска превысила затраты (оборудование, время). В простом виде:

```
окупаемость (мес.) = затраты на установку / (экономия в месяц)
```

Если затраты нулевые (компьютер есть) — окупаемость мгновенная, дальше чистый плюс.

## Как посчитать для себя (практика)

Соберите данные:

1. Сколько запросов вы делаете в месяц?
2. Сколько стоит один запрос в облаке (ваш тариф)?
3. Какая электроэнергия у вашего компьютера в месяц?
4. Есть ли затраты на железо/время?

Затем подставьте в модель расчёта выше (попросите агента оформить красиво).

## Частые проблемы

| Проблема | Решение |
|---|---|
| «Считаю, а цифры не сходятся» | Уточнить тарифы и реальный объём запросов |
| «Забыл про электроэнергию» | Учесть: компьютер под нагрузкой потребляет больше |
| «Забыл про качество/время» | Экономия в рублях не вся: качество тоже стоит |
| «Облако выгодно» | Малый объём или слабое железо — тогда да, облако |
