# Предлагаемые типы слайдов LearnByte

Черновик-спецификация новых типов слайдов, которых нет в `slides.md`, но которые
закрывают реальные потребности курсов «Генеративный ИИ на практике» и могут
пригодиться другим курсам. Формат — по образцу `slides.md`.

Статус: **предложение**. В `slides.md` не внесено, пока типы не реализованы
на платформе. После реализации — добавить строки в таблицу типов и разделы ниже
в `slides.md`, удалив этот файл.

---

## 1. `terminal` — Терминал (TerminalSlide / TerminalSlideEditor)

Запуск команд в shell на бэкенде с живым выводом в терминал. Закрывает главный
пробел курса: всё, что делается не через Python-редактор и не в ноутбуке, —
установка инструментов (Ollama, Gemini CLI, Open WebUI), рендер программ-роликов
(manim / pygame), запуск MCP-серверов, n8n, работа с файлами и директориями.

Поля `content`:

- `title` — заголовок.
- `task` — текст задания в Markdown перед терминалом (обязательно).
- `code` — начальная команда в поле ввода (может быть пустой).
- `shell` — `bash` (по умолчанию) | `zsh` | `powershell`.
- `working_dir` — рабочая директория относительно рабочего пространства студента
  (опционально; по умолчанию корень пространства).
- `timeout` — лимит выполнения одной команды в секундах (по умолчанию 60).
- `expected_output` — ожидаемый вывод для автопроверки (опционально; сравнение
  после нормализации регистра и пробелов, как в `code`).
- `description` — дополнительное описание под терминалом.

Поведение:

- Команды выполняются в **изолированной среде** (контейнер/песочница), общая
  файловая система с `code`/`jupyter` слайдами курса — рабочие файлы видны и там,
  и там.
- Секреты — только через файл `.env` в рабочей директории, который подгружается
  в окружение команды. Сами команды не логируются; значения секретов в вывод
  не печатаем.
- Автопроверка по `expected_output` (если задан) — кнопка «Проверить» появляется
  после выполнения.

Применение в курсах:

- Занятия 1–16 обоих семестров: рендер видео-скриптов из `videos/`.
- sem1 занятие 4: запуск собранного агента-«дежурного».
- sem2 занятия 12–13: `ollama run …`, установка и настройка Ollama / LM Studio.
- sem2 занятие 14: запуск Open WebUI.
- sem2 занятия 7, 9–10: установка и запуск Gemini CLI, MCP-серверов.

## 2. `ai_code_task` — Задание: код через AI (AICodeTaskSlide / AICodeTaskSlideEditor)

Воплощает ядро педагогики курса: **студент описывает задачу словами, агент пишет
код, студент запускает и проверяет результат**. Склеивает `ai_task_chat` + `code`
в один слайд с кнопкой «Вставить код в редактор» и AI-проверкой решения.

Устройство слайда:

- Блок «Задание» — текст задачи в Markdown.
- Чат с AI-агентом-кодером: студент просит написать код; агент отвечает.
  Кнопка «Вставить код в редактор» переносит код из последнего сообщения агента
  в редактор одним кликом.
- Редактор кода с кнопкой «Выполнить» и областью вывода (как в `code`).
- Кнопка «Проверить»: если задан `expected_output` — автопроверка вывода;
  иначе решение (задание + код + вывод) оценивает AI по `checkPrompt`.
- Кнопка «На самом деле все верно» (ручной пересмотр) — по аналогии
  с `ai_image_task`.

Поля `content`:

- `title` — заголовок.
- `task` — текст задания в Markdown (обязательно).
- `language` — `python` | `javascript` | `html` | `css` | `json`
  (по умолчанию `python`).
- `code` — начальный код в редакторе (опционально).
- `expected_output` — ожидаемый вывод для автопроверки (опционально; если задан —
  проверка автоматическая).
- `checkPrompt` — скрытый промпт для AI-проверки решения (опционально; нужен,
  если `expected_output` не задан или задача открытая).
- `insertCodeButton` — показывать кнопку «Вставить код в редактор»
  (по умолчанию true).
- Общие AI-настройки: `systemPrompt` (роль агента-кодера, Markdown),
  `aiName`, `model`, `chainOfThought`, `showSystemPrompt`, `showModelSelect`,
  `showCoT`, `allowFileUpload`, `showSettings`.

Проверка ответа: по `options` нет; автопроверка через `expected_output`
или AI через `checkPrompt` (код + вывод).

Применение в курсах:

- sem1 занятия 5, 6, 11–15: агент пишет RAG-поиск, скрипты с pandas, графики,
  вызовы API, извлечение PDF-таблиц.
- sem2 занятия 1–5 (химия): SMILES-инструменты, RDKit-расчёты, фильтры.
- sem2 занятия 8, 10: свой агент на SDK, свой MCP-сервер.
- Итоговые проекты (sem1 занятие 16, sem2 занятия 5, 11, 16).

## Задел на будущее (кратко, по убыванию приоритета)

Эти типы полезны, но не входят в первую пару. Расписать детально по запросу.

- **`llm_playground` — песочница параметров.** Слайдеры температуры, top-p,
  системный промпт, роли, few-shot; повторный прогон одного запроса. Для занятий
  по промпт-инжинирингу (sem1 2, 7, 8). Сейчас имитируется настройками `ai_chat`.
- **`ai_comparison` до 3–4 панелей.** Эксперимент «один запрос — разные роли/
  модели» (sem1 занятие 7) требует больше двух панелей; сейчас только 2.
- **`embed` — встроенный web-инструмент.** iframe с белым списком доменов
  (tiktokenizer, bbycroft.net/llm, TokenProbe). Сейчас даются ссылками
  в `rich_text`.
- **`resources` — файлы для скачивания.** Список файлов курса (CSV/JSON/PDF,
  шаблоны промптов) с кнопками скачивания. Сейчас файлы в `files/` и `links.md`.
- **`local_ai_chat` — чат с локальной моделью.** Поле кастомного `base_url`
  (Ollama / Open WebUI, OpenAI-совместимый endpoint) для sem2 занятия 14.
  Альтернатива: просто добавить `base_url` в настройки `ai_chat`.
