# Слайды LearnByte: справочник типов

Этот файл описывает все типы слайдов, доступные в LearnByte, чтобы LLM-инструмент
мог разбивать учебный контент на слайды правильного типа с правильными полями.

## Как устроен слайд

Каждый слайд хранится в структуре курса (`course.sections[].slides[]`) и имеет вид:

```json
{
  "id": 1,
  "section_id": 1,
  "order_index": 0,
  "slide_type": "rich_text",
  "content": { }
}
```

- `slide_type` — строка-код типа (см. таблицу ниже).
- `content` — объект с полями, специфичными для типа.
- `order_index` — порядок слайда внутри секции.

Маппинг кода на компонент отрисовки: `frontend/src/components/SlideRenderer`.
Выбор типа и редактор контента: `frontend/src/components/admin/SlideModal`.
Редакторы слайдов: `frontend/src/components/admin/editors/*`.

## Дополнительная информация: длинные тексты и ссылки `[текст](@слаг)`

Помимо слайдов, курс может содержать блоки «дополнительной информации» —
расширенные тексты, которые не помещаются в основной слайд и не обязательны для
изучения: история вопроса, глоссарий, справка, FAQ, дополнительные примеры.
Каждый такой блок — это заголовок + содержимое (Markdown, можно с формулами
и изображениями).

Блоки создаются и редактируются в редакторе курса на вкладке
**«Доп. информация»**. В этой же вкладке задаётся **слаг** блока — короткий
идентификатор латиницей (буквы, цифры, дефис, без пробелов), например `history`.

Чтобы связать слайд с блоком, добавьте в Markdown слайда ссылку вида
`[текст](@слаг)`:

```markdown
Подробнее об этом — [в истории компании](@history).
```

Ссылка отображается с иконкой мозга; по клику открывается окно с содержимым
блока (заголовок + текст), которое можно закрыть. Ссылку можно ставить в любом
слайде с Markdown — в лекциях, заданиях, сообщениях AI-чатов. Блоки также могут
ссылаться друг на друга.

Рекомендации:
- Слайд должен оставаться самодостаточным: краткое изложение + ссылка
  `[подробнее](@слаг)` на блок вместо большого текста.
- Ссылайтесь на блоки только по их слагу и убедитесь, что слаг существует,
  иначе ссылка не откроется.
- Блоки подходят для справочных материалов: история, глоссарий, FAQ,
  расшифровка терминов, дополнительные примеры.


## Общие настройки AI-чатов (`ChatSettingsEditor`)

Большинство AI-слайдов используют общий блок настроек:

- `systemPrompt` — системный промпт (роль модели), Markdown-строка.
- `aiName` — отображаемое имя AI (по умолчанию «AI-ассистент»).
- `model` — модель (по умолчанию `openrouter/free`); пусто = пользователь выбирает.
- `chainOfThought` — фиксированное включение Chain of Thought.
- `showSystemPrompt` — показывать пользователю system prompt (по умолчанию true).
- `showModelSelect` — показывать выбор модели (по умолчанию true).
- `showCoT` — показывать переключатель CoT (по умолчанию true).
- `allowFileUpload` — разрешить загрузку файлов (по умолчанию true).
- `showSettings` — показывать панель настроек (по умолчанию true).

Локальный провайдер (Ollama / Open WebUI на машине студента):

- `useLocalProvider` — использовать локальный провайдер (true/false).
- `baseUrl` — корень OpenAI-совместимого endpoint'а, например
  `http://localhost:11434/v1`.
- `localToken` — опциональный API-токен.

Бэкенд не может достучаться до `localhost` студента, поэтому запрос пересылается
через **JS-прокси в браузере**: бэкенд создаёт relay-задачу и отдаёт payload по
SSE (`GET /api/ai/local/relay/{id}`), браузер отправляет его на локальный
провайдер и возвращает результат (`POST /api/ai/local/relay/{id}/result`).
Для Ollama нужно разрешить CORS: запустить с `OLLAMA_ORIGINS=*`.

Для image-вариантов (`ai_image_gen`, `ai_image_task`) вместо части чат-настроек
используются:

- `model` — модель генерации изображений (по умолчанию `@cf/black-forest-labs/flux-1-schnell`).
- `size` — размер изображения: `256x256`, `512x512`, `1024x1024`, `1024x1792`, `1792x1024` (по умолчанию `512x512`).
- `checkModel` — модель для проверки результата (vision).
- `showCheckModelSelect` — показывать выбор модели проверки (по умолчанию true).

## Таблица типов слайдов

| Код (`slide_type`) | Слайд-компонент | Назначение | Проверка ответа |
|---|---|---|---|
| `welcome` | WelcomeSlide | Приветствие курса | нет |
| `video` | VideoSlide | Видео (YouTube / MP4) | нет |
| `image` | ImageSlide | Одиночное изображение | нет |
| `rich_text` | RichTextSlide | Лекционный текст (Markdown + LaTeX) | нет |
| `code` | CodeSlide | Редактор кода с выполнением | `expected_output` |
| `jupyter` | ReplSlide | Встроенный Jupyter REPL | нет |
| `quiz` | QuizSlide | Квиз или опрос с вариантами | по `options[].is_correct` |
| `open_question` | OpenQuestionSlide | Открытый вопрос с вводом текста | по `correct_answers` |
| `congrats` | CongratsSlide | Финальный экран + отчет | нет |
| `ai_chat` | AIChatSlide | Свободный чат с AI | нет |
| `ai_comparison` | AIComparisonSlide | 2–4 AI-чата рядом | нет |
| `ai_task_chat` | AITaskChatSlide | Диалог с AI как задание | AI (checkAnswer) |
| `ai_fixed_answer` | AIFixedAnswerSlide | Чат + фиксированный ответ | по `correct_answers` |
| `ai_image_gen` | AIImageGenSlide | Свободная генерация изображений | AI (по изображению) |
| `ai_image_task` | AIImageTaskSlide | Задание на генерацию изображения | AI (по изображению) |
| `ai_code_task` | AICodeTaskSlide | Задание: чат с AI + код | `expected_output` или AI (checkAnswer) |
| `terminal` | TerminalSlide | Терминал (shell в песочнице) | `expected_output` |
| `image_group` | ImageGroupSlide | Галерея изображений в сетке | нет |
| `llm_playground` | LLMPlaygroundSlide | Песочница параметров LLM | нет |
| `embed` | EmbedSlide | Встроенный web-инструмент (iframe) | нет |
| `resources` | ResourcesSlide | Файлы для скачивания | нет |

## Подробно по каждому типу

### `welcome` — Приветствие (WelcomeSlide / WelcomeSlideEditor)

Приветственный экран курса: название, подзаголовок, преподаватель, длительность,
кнопка «Начать». Если в курсе есть AI-слайды, для неавторизованных показывается
баннер о необходимости регистрации.

Поля `content`:
- `title` — название курса (обязательно).
- `subtitle` — подзаголовок / краткое описание.
- `instructorName` — имя преподавателя.
- `instructorAvatar` — URL аватара.
- `duration` — длительность (например «7 дней»).
- `lessonsCount` — количество уроков (опционально, отображается иконкой).

### `video` — Видео (VideoSlide / VideoSlideEditor)

Встраивает YouTube-видео или прямой файл (MP4/WebM).

Поля `content`:
- `title` — заголовок.
- `video_url` — URL: ссылка на YouTube (`youtube.com/watch?v=`, `youtu.be/`) или прямая ссылка на файл.
- `video_type` — `youtube` | `vimeo` | `direct`. Определяется также автоматически по URL.
- `autoplay` — автовоспроизведение.
- `description` — подпись под видео.

### `image` — Изображение (ImageSlide / ImageSlideEditor)

Одиночное изображение на весь слайд.

Поля `content`:
- `title` — заголовок.
- `image_url` — URL изображения (обязательно).
- `alt_text` — альтернативный текст.
- `description` — подпись под изображением.

### `rich_text` — Текст (RichTextSlide / RichTextSlideEditor)

Лекционный текст. Поддерживает Markdown, LaTeX (Katex), изображения, таблицы, код.

Поля `content`:
- `title` — заголовок (H1).
- `markdown` — основной контент в Markdown (обязательно).

Используйте для объяснения материала, теории, примеров, списков.
Длинные «приложения» выносите в блоки дополнительной информации и ссылайтесь
на них из Markdown: `[подробнее](@слаг)` (см. раздел «Дополнительная
информация» выше).

### `code` — Код (CodeSlide / CodeSlideEditor)

Редактор кода (Monaco) с кнопкой «Выполнить». Python выполняется на бэкенде,
JavaScript/HTML/CSS/JSON — на фронтенде. Если задан `expected_output`, результат
проверяется автоматически (сравнение после нормализации регистра и пробелов).

Поля `content`:
- `title` — название.
- `language` — `javascript` | `python` | `html` | `css` | `json` (по умолчанию `javascript`).
- `task` — текст задания перед редактором.
- `code` — начальный код (может быть пустым).
- `expected_output` — ожидаемый вывод программы для автопроверки (опционально).
- `description` — дополнительное описание.

### `jupyter` — Jupyter REPL (ReplSlide / ReplSlideEditor)

Встраивает интерактивный Jupyter-REPL в iframe (сервер на порту 8888).
Клетки пользователя автосохраняются в прогресс.

Поля `content`:
- `title` — название.
- `kernel` — ядро: только `pyodide` (Python).
- `task` — текст задания.
- `code` — начальный код.
- `description` — дополнительное описание.

### `quiz` — Квиз / Опрос (QuizSlide / QuizSlideEditor)

Вопрос с вариантами ответов. Если хотя бы у одного варианта `is_correct=true` —
это квиз с проверкой и кнопкой «Продолжить». Если правильных вариантов нет — это
опрос (без обратной связи, ответ засчитывается автоматически).

Поля `content`:
- `question` — текст вопроса (обязательно).
- `markdown` — дополнительный текст вопроса (Markdown/LaTeX).
- `options` — массив `[{ text, is_correct }]`. Минимум 2 варианта.
- `explanation` — объяснение правильного ответа (показывается после ответа).

### `open_question` — Открытый вопрос (OpenQuestionSlide / OpenQuestionSlideEditor)

Текстовый ввод ответа с проверкой по списку правильных ответов. Сравнение
case-insensitive с удалением лишних пробелов; при `fuzzy_match` допускает опечатки.

Поля `content`:
- `question` — текст вопроса (обязательно).
- `markdown` — дополнительный текст вопроса (Markdown/LaTeX).
- `correct_answers` — массив правильных ответов (каждый с новой строки).
- `correct_answer` — первый правильный ответ (для обратной совместимости).
- `congratulations` — сообщение при правильном ответе.
- `error_message` — сообщение при неправильном ответе.
- `hint` — подсказка при ошибке.
- `show_correct_answer` — показывать правильный ответ при ошибке.
- `fuzzy_match` — нечеткое сравнение (учитывает опечатки).
- `similarity_threshold` — порог схожести для нечеткого сравнения (0.0–1.0, по умолчанию 0.8).

### `congrats` — Поздравление (CongratsSlide, без редактора)

Финальный слайд: конфетти, «Поздравляем!», кнопка «Завершить», кнопка «Скачать
отчет» (генерирует PDF по прогрессу студента), ссылка «К другим курсам».

Поля `content`:
- `message` — подпись под заголовком (по умолчанию «Вы успешно завершили курс!»).

### `ai_chat` — Чат с AI (AIChatSlide / AIChatSlideEditor)

Свободный диалог с AI-моделью. Сообщения автосохраняются в прогресс.

Поля `content`:
- `title` — заголовок (опционально).
- `task` — описание задания в Markdown (опционально, показывается в блоке «Задание»).
- Общие AI-настройки (см. выше).

### `ai_comparison` — Сравнение моделей (AIComparisonSlide / AIComparisonSlideEditor)

От 2 до 4 AI-чатов рядом (панели), позволяющие сравнить ответы моделей.
Вопрос можно отправить во все панели сразу через общее поле ввода.

Поля `content`:
- `title` — заголовок.
- `mergeInput` — объединять поле ввода сообщений (одно поле вместо нескольких).
- `panels` — массив панелей `[{ label, model, systemPrompt, aiName,
  chainOfThought, showSystemPrompt, showModelSelect, showCoT, allowFileUpload,
  showSettings, useLocalProvider, baseUrl, localToken }]`. По умолчанию 2 панели
  (модель A: `openrouter/free`, модель B: `openai/gpt-oss-20b:free`).

Для обратной совместимости со старой схемой (левая/правая панель) поддерживаются
поля `labelLeft`/`labelRight` и настройки с суффиксами `Left`/`Right`
(`systemPromptLeft`, `modelLeft`, `chainOfThoughtLeft` и т.д.) — если `panels`
не задан, из них строятся две панели.

### `ai_task_chat` — Задание: чат с AI (AITaskChatSlide / AITaskChatSlideEditor)

Диалог с AI как учебное задание. Студент отправляет сообщение, AI отвечает, затем
можно нажать «Проверить» — выбранный ответ AI проверяется через бэкенд
(`api.ai.checkAnswer`) с опциональным `checkPrompt`.

Поля `content`:
- `task` — текст задания в Markdown (обязательно).
- `checkPrompt` — скрытый промпт для проверки ответа (опционально).
- Общие AI-настройки (см. выше).

### `ai_fixed_answer` — Чат с фикс. ответом (AIFixedAnswerSlide / AIFixedAnswerSlideEditor)

Комбинация чата с AI и текстового поля фиксированного ответа. Студент общается
с AI, затем вводит ответ и отправляет; проверка по списку правильных ответов
(как в `open_question`).

Поля `content`:
- `question` — название слайда (обязательно).
- `task` — описание задания в Markdown.
- `correct_answers` — массив правильных ответов.
- `correct_answer` — первый правильный ответ (обратная совместимость).
- `congratulations` / `error_message` / `hint` — сообщения обратной связи.
- `fuzzy_match` / `similarity_threshold` — настройки нечеткого сравнения.
- Общие AI-настройки (см. выше).

### `ai_image_gen` — Генерация изображений (AIImageGenSlide / AIImageGenSlideEditor)

Свободная генерация изображений: студент пишет промпт и получает изображение.
Без заранее заданного задания; по желанию доступна кнопка «Проверить»
(AI оценивает, соответствует ли картинка промпту).

Поля `content`:
- `title` — заголовок.
- `checkPrompt` — скрытый промпт для проверки (опционально).
- `checkModel` — модель проверки (vision).
- `showCheckModelSelect` — показывать выбор модели проверки.
- Image-настройки: `model`, `size` (см. выше).

### `ai_image_task` — Задание: генерация (AIImageTaskSlide / AIImageTaskSlideEditor)

Задание: сгенерировать изображение, соответствующее заданию. Проверка
выполняется AI по изображению; есть кнопка «На самом деле все верно» (ручной
пересмотр результата).

Поля `content`:
- `task` — текст задания в Markdown (обязательно).
- `checkPrompt` — скрытый промпт для проверки (опционально).
- `checkModel` — модель проверки (vision).
- `showCheckModelSelect` — показывать выбор модели проверки.
- Image-настройки: `model`, `size` (см. выше).

### `ai_code_task` — Задание: AI + код (AICodeTaskSlide / AICodeTaskSlideEditor)

Воплощает ядро педагогики курса: студент описывает задачу словами, агент пишет
код, студент запускает и проверяет результат. Склеивает `ai_task_chat` + `code`
в один слайд.

Устройство слайда:
- Блок «Задание» — текст задачи в Markdown.
- Чат с AI-агентом-кодером; под ответом агента с fenced-блоком кода — кнопка
  **«Вставить код в редактор»** (переносит код из последнего сообщения агента
  в редактор и переключает на вкладку «Код»; на табе «Код» появляется бейдж `!`).
- Вкладка «Код»: Monaco-редактор с кнопкой «Выполнить» и областью вывода
  (Python — бэкенд, JS/HTML/CSS/JSON — фронтенд).
- Кнопка «Проверить»: если задан `expected_output` — автопроверка вывода
  (сравнение после нормализации регистра и пробелов); иначе решение
  (задание + код + вывод) оценивает AI по `checkPrompt`.
- Кнопка «На самом деле все верно» (ручной пересмотр) — как в `ai_image_task`.

Поля `content`:
- `title` — заголовок.
- `task` — текст задания в Markdown (обязательно).
- `language` — `python` (по умолчанию) | `javascript` | `html` | `css` | `json`.
- `code` — начальный код в редакторе (опционально).
- `expected_output` — ожидаемый вывод для автопроверки (опционально; если задан —
  проверка автоматическая).
- `checkPrompt` — скрытый промпт для AI-проверки решения (опционально; нужен,
  если `expected_output` не задан).
- `insertCodeButton` — показывать кнопку «Вставить код в редактор» (по умолчанию true).
- Общие AI-настройки (см. выше).

Сохранение в прогресс (`data`): `messages`, `user_code`, `output`, `error`,
`language`, `attempts` (счётчик запусков), `checked`, `isCorrect`,
`ai_overridden`, `resultExplanation`.

### `terminal` — Терминал (TerminalSlide / TerminalSlideEditor)

Запуск команд в shell с живым выводом. Команды выполняются в изолированной
**песочнице** (chroot-jail) отдельным docker-сервисом `sandbox` от пользователя
`nobody`; выводимый текст стримится по SSE (`POST /api/terminal/exec` —
бэкенд-прокси на `sandbox:8700/exec`). Рабочее пространство студента —
`storage/workspaces/<session_id>` (общее для всех команд слайда; переживает
перезагрузку страницы). Секреты — из файла `.env` в корне workspace
(подгружается в окружение команды, значения маскируются в выводе).

Поля `content`:
- `title` — заголовок.
- `task` — текст задания в Markdown (обязательно).
- `code` — начальная команда, подставляемая в поле ввода (опционально).
- `shell` — `bash` (по умолчанию) | `zsh` | `powershell`. Если выбранного shell
  нет в песочнице — используется `bash`.
- `working_dir` — стартовая рабочая директория относительно рабочего пространства
  студента (опционально). Далее `cd` отслеживается автоматически.
- `timeout` — лимит выполнения одной команды в секундах (по умолчанию 60).
- `expected_output` — ожидаемый вывод для автопроверки (опционально; сравнивается
  с выводом последней команды после нормализации регистра и пробелов; если не
  задан — кнопка «Проверить» скрыта).
- `description` — дополнительное описание.

Поведение:
- Enter — выполнить команду, Shift+Enter — новая строка (мультистрочные команды).
- Рабочая директория отслеживается на клиенте (`cd` из команды применяется к
  следующей), выйти за пределы workspace нельзя.
- Каждая команда выполняется в свежем shell (состояние shell не переносится
  между командами; файлы — переносятся).
- По таймауту процесс убивается группой (`SIGKILL`).
- Кнопка «Проверить» появляется после выполнения, если задан `expected_output`;
  есть «На самом деле все верно».

Сохранение в прогресс (`data`): `history` (массив `{cmd, shell, cwd, ts,
exit_code, output}`), `cwd`, `checked`, `isCorrect`, `ai_overridden`.

### `image_group` — Группа изображений (ImageGroupSlide / ImageGroupSlideEditor)

Галерея изображений в сетке (авто-колонки: 1–2–3–4 в зависимости от числа
картинок). Клик по картинке открывает полноэкранный лайтбокс с навигацией.

Поля `content`:
- `title` — заголовок.
- `images` — массив URL изображений (drag-and-drop порядок).
- `show_frames` — показывать рамки вокруг картинок.
- `description` — описание под галереей.

### `llm_playground` — Песочница параметров (LLMPlaygroundSlide / LLMPlaygroundSlideEditor)

Свободный эксперимент с параметрами генерации: студент пишет запрос, крутит
слайдеры температуры / top-p / max_tokens, добавляет few-shot примеры и смотрит
ответ модели. У каждого запуска есть кнопка **«Повторить»** — повторный прогон
того же запроса с теми же параметрами. Прогоны сохраняются в прогресс.

Поля `content`:
- `title` — заголовок.
- `task` — инструкция для студента в Markdown.
- `defaultPrompt` — запрос, подставленный по умолчанию.
- `systemPrompt` — системный промпт.
- `model` — модель (по умолчанию `openrouter/free`).
- `showModelSelect` — показывать выбор модели.
- `showSystemPrompt` — показывать системный промпт.
- `showTemperature` / `temperature` — показывать слайдер температуры / значение по умолчанию.
- `showTopP` / `topP` — показывать слайдер top-p / значение по умолчанию.
- `showMaxTokens` / `maxTokens` — показывать слайдер max_tokens / значение по умолчанию
  (слайдер ограничен диапазоном 1–4096).
- `showFewShots` / `fewShots` — показывать few-shot примеры / примеры по умолчанию
  (`[{ role: 'user'|'assistant', content }]`).
- `allowRerun` — показывать кнопку «Повторить» (по умолчанию true).
- Настройки локального провайдера: `useLocalProvider`, `baseUrl`, `localToken`.

### `embed` — Встроенный web-инструмент (EmbedSlide / EmbedSlideEditor)

Встраивает произвольный web-инструмент. Слайд оформлен как окно браузера
с «адресной строкой» (только для чтения). Список разрешённых доменов не
ограничивается — администратор вводит любой URL.

Поля `content`:
- `title` — заголовок.
- `url` — URL встраиваемого инструмента (обязательно).
- `mode` — режим открытия (`direct` по умолчанию, `proxy` или `browser`).
- `description` — краткая инструкция в Markdown.

Режимы открытия:

- **`direct`** — обычное встраивание в iframe. Многие сайты блокируют через
  X-Frame-Options / CSP; в этом случае адресная строка остаётся видимой, чтобы
  студент мог открыть инструмент в новой вкладке.
- **`proxy`** — сайт загружается бэкендом через SOCKS5-прокси (birdman) и
  раздаётся по `/api/proxy/{token}/{url}` (короткоживущий JWT, ~60 мин,
  выдаётся авторизованному студенту). HTML/CSS переписываются: same-origin
  ресурсы идут через прокси, кросс-доменные — грузятся напрямую; в `<head>`
  внедряется bootstrap-скрипт, перенаправляющий `fetch`/`XHR`/`EventSource`/
  динамические `src`/`href` страницы через прокси. Куки и WebSockets целевого
  сайта не поддерживаются; кросс-доменные JS API-вызовы остаются прямыми
  (CORS / SSRF-риск). Токен привязан к домену слайда (из БД): проксируется
  только тот же host:port; http→https разрешён, https→http и чужие домены
  запрещены (включая адреса после редиректов). Приватные/локальные адреса
  запрещены.
- **`browser`** — сайт выполняется в серверном Chromium (сервис `browser`,
  CDP/puppeteer) и транслируется JPEG-кадрами через WebSocket
  (`/api/browser/ws`). Работает всё, включая WebSockets и авторизацию сайта.
  Взаимодействие — мышь/колесо/клавиатура; viewport адаптируется под размер
  слайда. Требует ресурсов: максимум одновременных сессий задаётся в
  `.env` как `BROWSER_MAX_SESSIONS` (по умолчанию 4), простой сессии —
  `BROWSER_SESSION_TTL_SEC` (600). URL сессии тоже ограничивается доменом
  слайда из БД (тот же host:port).

### `resources` — Файлы для скачивания (ResourcesSlide / ResourcesSlideEditor)

Список файлов курса с кнопками «Скачать».

Поля `content`:
- `title` — заголовок.
- `description` — описание в Markdown.
- `files` — массив `[{ name, url, description }]` — название, ссылка и краткое
  описание файла (`description` опционально).

## Рекомендации по выбору типа

- Теория, объяснение, примеры → `rich_text` (или `video`/`image` для наглядности).
- Практика программирования → `code` (с `expected_output` для автопроверки)
  или `jupyter` для интерактивных notebook-подобных занятий.
- Задание «агент пишет код, студент запускает и проверяет» → `ai_code_task`.
- Работа в shell: установка инструментов, запуск сервисов, работа с файлами
  и директориями → `terminal`.
- Проверка понимания → `quiz` (закрытые вопросы) и `open_question` (открытые).
- Изучение/практика с AI → `ai_chat` (свободный), `ai_task_chat` (с проверкой),
  `ai_fixed_answer` (точный ответ), `ai_comparison` (сравнение моделей).
- Генеративные практики → `ai_image_gen` (свободная) или `ai_image_task` (с заданием).
- Иллюстрации, доска, коллаж → `image_group`.
- Эксперименты с параметрами генерации (температура, top-p, few-shot) → `llm_playground`.
- Встроенные web-инструменты и песочницы → `embed`.
- Раздаточные материалы, файлы → `resources`.
- Первый слайд курса → `welcome`; последний → `congrats`.
- Длинные справочные тексты (история, глоссарий, FAQ) → блоки дополнительной
  информации с ссылками `[подробнее](@слаг)` в слайдах.

## Задел на будущее (идеи, не реализовано)

Реализовано ранее: `llm_playground` (песочница параметров), `ai_comparison`
до 3–4 панелей, `embed` (встроенный web-инструмент), `resources` (файлы для
скачивания), чат с локальным провайдером (Ollama / Open WebUI) через
`useLocalProvider`/`baseUrl` в настройках AI-чатов. См. разделы выше.

Остались идеи:

- **Персональные модели в `ai_chat`.** Позволить студенту добавить свой кастомный
  `base_url` на лету (без настройки слайда преподавателем).
- **Пакетное сравнение в `ai_comparison`.** Один запрос — ответы 2–4 моделей на
  одном экране без ручного прогона.
- **`resources` с прогрессом.** Отмечать скачанные файлы как изученные.
- **`embed` с allowlist.** Опциональный белый список доменов и «песочница»
  для недоверенных URL.
- **`local_ai_chat` как отдельный тип.** Отдельный слайд-тип, если настройки
  в общем `ChatSettingsEditor` окажутся недостаточно заметными.
